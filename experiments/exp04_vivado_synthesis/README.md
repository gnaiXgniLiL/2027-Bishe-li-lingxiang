# EXP04：原始 CPU＋CFU 设计的 Vivado 实现与时序验证

## 1. 实验目的

在真实 FPGA 工具链中完成原始 CPU＋CFU 设计的综合、布局布线和比特流生成，记录全系统资源占用，并验证不同目标频率下的时序收敛情况。

## 2. 实验平台

- Vivado：2026.1
- 开发板：Nexys A7
- 器件：xc7a100tcsg324-1
- 顶层模块：main
- 报告阶段：Physopt postRoute
- RTL：两次实验保持一致，仅修改 CLK_FREQ_MHZ

## 3. 实验设计

第一次目标频率为 160 MHz，第二次降低为 80 MHz。
两次均执行综合、实现和比特流生成，并保存实现后的资源与时序报告。

80 MHz 实验前预测：时钟周期由 6.250 ns 放宽至 12.500 ns，
建立时间裕量应明显改善，资源数量应大体接近，80 MHz 有机会实现时序收敛。
最终结论以 postRoute 报告为准。

## 4. 实测结果

| 指标 | 160 MHz | 80 MHz |
|---|---:|---:|
| 时钟周期（ns） | 6.250 | 12.500 |
| Slice LUTs | 1804 | 1746 |
| Slice Registers（FF） | 918 | 884 |
| DSP | 7 | 7 |
| BRAM Tile | 19 | 19 |
| WNS（ns） | -5.026 | +0.045 |
| TNS（ns） | -386.248 | 0.000 |
| 建立时间失败端点 | 361 | 0 |
| WHS（ns） | +0.024 | +0.056 |
| 时序结论 | 未收敛 | 收敛 |

两次实现均成功生成比特流，但生成比特流不等于时序收敛。

资源数据为整个 main 顶层设计的统计，包含 CPU、CFU、存储器和时钟模块，
不能视为 CFU 单元的单独资源开销。

## 5. 预测对照与结论

80 MHz 结果符合实验前预测：周期放宽后，WNS 从 -5.026 ns 提升至
+0.045 ns，建立时间失败端点从 361 降为 0。DSP 和 BRAM 数量不变，
LUT 和 FF 因不同目标下的实现优化而略有变化。

两次最差路径均通向 CFU 累加寄存器，并包含 DSP 和进位逻辑，
说明 CFU 乘加组合路径是当前时序优化的重要对象。

当前只证明原始设计在 80 MHz 下满足已给定的时序约束。
尚未完成更细粒度的频率扫描，因此不能把 80 MHz 直接写成最终 Fmax。

## 6. 当前限制与后续工作

- 尚未进行 85 MHz 及更高频率的细分测试。
- 尚未单独统计 CFU 模块的层次化资源。
- XDC 中仍存在时钟重复定义和部分端口无匹配等警告，后续需要审查。
- 时序报告仍提示 4 个输出端口没有 output delay，后续需要确认其影响。
- 后续优化可考虑拆分或流水化 CFU 乘加组合路径。
