## 预测：
256 维点积 CFU 版相对纯 C 版加速约 1.3–1.6 倍。依据：每次迭代省掉 mul 多拍停顿与一条 add，但两次 lw 与循环控制开销两边相同，由 Amdahl 定律，加速比被未加速部分限制。

## 实测结果（2026-10-06）
- 纯 C：avg 2825 拍/次（≈11.0 拍/迭代）；CFU：avg 1798 拍/次（≈7.0 拍/迭代）
- 加速比 1.57x，落在预测区间 1.3–1.6 上沿
- 归因：每次迭代省 ≈4 拍 = mul FSM 停顿（2~3 拍）+ add（1 拍）；lw×2 与循环控制两边相同省不掉，符合 Amdahl 定律
- 正确性：c=-23637 cfu=-23637 逐位一致



| 优化级别 | 纯 C avg | CFU avg | 加速比      | C 每迭代   | CFU 每迭代 | **每迭代节省** |
| ---- | ------- | ------- | -------- | ------- | ------- | --------- |
| -O0  | 7462    | 6428    | **1.16** | ≈29.1 拍 | ≈25.1 拍 | ≈4.0 拍    |
| -Os  | 2825    | 1798    | **1.57** | ≈11.0 拍 | ≈7.0 拍  | ≈4.0 拍    |
| -O2  | 2570    | 1798    | **1.42** | ≈10.0 拍 | ≈7.0 拍  | ≈3.0 拍    |


1. -O0 下加速比反而最小（1.16），CFU 版里也有普通指令——-O0 下 CFU 版的 lw、循环控制、函数调用同样变慢（1798 → 6428）。关键规律：每次迭代的绝对节省是恒定的 ≈4 拍（CFU_MAC 替换 mul+add 省的那部分），变的是两边的"底座开销"。底座越大，固定 4 拍占比越小，比值越趋近 1。这是 Amdahl 定律的第二种表现形式：绝对收益固定时，相对加速比随基础开销膨胀而缩水。
2. CFU 版在 -Os 和 -O2 下完全相同（1798）。 因为 asm volatile 禁止编译器碰那几条 CFU 指令，循环已经最紧，编译器没有可优化空间——说明 CFU 版性能由硬件和指令开销决定，与编译器无关。这本身是"硬件加速稳定性"的论据。
3. -O2 的 C 版比 -Os 还快（2570 < 2825），每迭代节省缩到 3 拍。 编译器优化确实在帮软件版追回一部分差距——编译器优化对软件版有效、对 CFU 版无效，所以编译器优化会吃掉一部分 CFU 的加速比。

### 规律分析

1. **点积加速比（1.57@-Os）符合预测区间 1.3–1.6**。逐拍归因：每次迭代省约 4 拍
   （mul 多拍 FSM 停顿 2~3 拍 + 一条 add），lw×2 与循环控制两边相同、省不掉。
   每迭代绝对节省恒定（≈4 拍），因此优化级别越低、基础开销越大，相对加速比
   越趋近 1（-O0 仅 1.16）——Amdahl 定律的直接体现。
2. **卷积加速比（2.56@-Os）显著高于点积，超出预测**。原因：CFU 版采用
   "预加载 + 完全展开"结构，9 条 MAC 连续发射，消除了内层循环控制开销；
   加速收益 = MAC 指令本身节省 + 循环展开节省，两部分叠加。
3. CFU 版在 -Os 与 -O2 下 cycle 数几乎不变（asm volatile 固定了指令序列），
   而纯 C 版随优化级别提升明显变快——编译器优化会部分蚕食硬件加速比。



## 异常分析

### proc.v 的 load-use 冒险未覆盖 custom-0 指令

- **现象**：conv3x3 CFU 版对拍 5/36 通过，错误呈"行冻结"规律——
  第 0 行全对，其余每行结果精确等于第 0 行对应列的结果。
- **排除过程**：① 怀疑内层 t/K、t%K 除法 → 实验 1（CFU 版改计数器消去除法）
  仍失败、实验 2（纯 C 版加除法）结果正确 → 除法排除；
  ② 探针 T1（组合 MUL 直读刚加载的值）出错、E1（相同数据纯 C 计算）正确
  → 定位到 custom-0 指令的操作数通路，与 acc 无关。
- **定位**：proc.v 中 hazard 信号 If_load_muldiv_use 对 load-use 只停顿一拍，
  且 CFU 仅在"生产者"一侧被列入；lw 数据经同步 RAM 晚一拍返回，
  custom-0 作为"消费者"紧跟 lw 时读到旧值。
- **验证**：T3/T4 探针表明 lw 与 custom-0 之间隔 1 条任意指令即正确。
- **规避**：CFU 代码采用"预加载 + 展开"结构（所有 load 在 CFU 指令序列之前
  完成），并在 CFU_OP 宏中前置 nop 双保险（当前每条 CFU 指令含 3 拍 nop 税）。
- **后续**：修改 proc.v 的 hazard 逻辑，将 custom-0 纳入 load-use 停顿，
  可去除 nop 税——留作方案 B 阶段的候选工作。
