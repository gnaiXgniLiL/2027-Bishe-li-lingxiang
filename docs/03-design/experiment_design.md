## 0. 设计原则

本课题全部实验遵循以下三条原则（已在 Baseline 阶段验证其价值）：

1. **先预测，后实测**：每个实验在跑之前先写下预测结果与依据，实测后对照分析偏差。偏差本身就是发现（如 conv3x3 加速比 2.56× 超出预测，引出了对循环控制开销的重新归因）。
2. **先对拍，后计时**：任何 CFU 版本必须先与纯 C 参考实现逐位比对（bit-exact）通过，才允许进入性能测量。功能不正确的性能数据无意义。
3. **单变量控制**：每组实验只改变一个变量（优化级别 / 并行度 / 位宽 / hazard 修复），其余配置冻结，配置记入 `config.yaml`，命令记入 `command.txt`。

## 1. 四问框架

### Q1：和谁比较？

| 层级 | 对比对象 | 说明 |
| --- | --- | --- |
| 核心基线 | 纯软件 C 实现（同一 RVProc 软核） | 每个 kernel 在 **-O0 / -Os / -O2** 三个优化级下各测一遍，证明软件侧已尽力（老师方案中明确要求） |
| 方案 A | 单周期单 MAC CFU（已完成） | `CFU_MUL/LOAD/READ/MAC` 四指令，预加载+展开结构 |
| 方案 B | 并行 / 打包 MAC CFU（待设计） | 候选方向见 §2.3，是本课题"优化"二字的主要载体 |
| 外部参照（仅定性） | CFU-PG 官方 FFT 5.1× / N-Queens 18.1×；PULP-NN 单核 INT8 8.8×；Yildirim & Ozturk (2025) 59.3× | 平台、位宽、算子不同，只做定性对照与差距归因，不做严格横向比较 |

### Q2：测哪些指标？

| 类别 | 指标 | 测量方式 | 备注 |
| --- | --- | --- | --- |
| 正确性 | 逐位对拍通过率 | CFU 输出 vs 纯 C 参考输出 | **一票否决项**，单独成节写进论文 |
| 性能 | cycle 数（均值） | `pg_perf` 计数器夹 10 次取总、扣空夹开销、除 10 | 确定性公式初始化，禁用 `rand` |
| 性能 | 加速比 | 同优化级下 纯C cycle ÷ CFU cycle | 按 kernel 级与整网级两级统计 |
| 资源 | LUT / FF / DSP / BRAM | Vivado 综合报告（`utilization`） | Nexys A7-100T（xc7a100tcsg324-1） |
| 时序 | Fmax / WNS | Vivado 时序报告 | 【待确认：工程目标频率，以 CFU-PG 默认约束为准】 |

不做能效（功耗）测量：仿真+综合流程下功耗数据可信度低，且非本课题核心命题，论文中说明即可。

### Q3：每个实验改变什么变量？

| 变量 | 取值 | 出现在 |
| --- | --- | --- |
| 编译优化级别 | -O0 / -Os / -O2 | Baseline + 主实验（证明软件侧已尽力 + 观察 Amdahl 效应） |
| CFU 并行度 | 1 / 2 / 4 MAC | 消融实验 |
| 数据位宽 | INT32 → INT8 packed（单寄存器装 4 个 INT8） | 消融实验 / 方案 B 候选 |
| hazard 修复 | 前置 3 nop 保险 vs 修 `proc.v` hazard 逻辑后去 nop | 消融实验（当前每条 CFU 指令 +3 拍税） |
| kernel 规模 | dot 长度、conv 输入尺寸（如 8×8 → 更大） | 参数实验（观察加速比随规模的变化趋势） |

### Q4：什么结果算"方法/系统有效"？

判据分必要条件与充分条件两层。**数值目标为预先写下的预测，实测后对照，不达标必须归因**。

| 判据 | 阈值 | 性质 |
| --- | --- | --- |
| C1 功能正确 | 所有测试用例（含负×正、大数、边界尺寸）逐位对拍 100% 通过 | **必要条件** |
| C2 kernel 级加速 | 方案 A：conv3x3 ≥ 2×、dot ≥ 1.3×（已达成 2.56× / 1.57×） | 充分条件（Baseline 已验证） |
| C3 方案 B 相对提升 | 方案 B 相对方案 A，conv kernel 加速比再提升 ≥【待你确认：建议 1.5×，依据是 MAC4 摊薄取指/循环开销后的理论上限估算】 | 充分条件（主实验） |
| C4 时序不退化 | 加入 CFU 后 Fmax 不低于原 RVProc 软核的【待确认】目标频率（WNS ≥ 0） | 必要条件（综合） |
| C5 资源可承受 | 方案 B 增量资源（相对方案 A）占板卡总量 ≤【待你确认：建议 LUT ≤10%、DSP 按需】 | 充分条件（综合） |
| C6 整网端到端 | 至少一个小型 CNN（LeNet 级）端到端推理跑通，整网加速比 ≥ 1（证明算子级收益能传导到整网） | 充分条件（拓展） |

## 2. 实验矩阵（四类实验）

### 2.1 EXP-B：Baseline 实验  已完成

- **目的**：建立纯软件性能基线 + 验证方案 A 的 kernel 级收益。
- **配置**：dot256（256 元素点积）、conv3x3（8×8 输入、3×3 卷积 → 6×6 输出）；RV32IM 软核；三档优化级。
- **结果**（详见 `experiments/baseline/metrics.csv`）：

| kernel | 优化级 | 纯 C avg(cycle) | CFU avg(cycle) | 加速比 |
| --- | --- | --- | --- | --- |
| dot256 | -O0 | 7462 | 6428 | 1.16 |
| dot256 | -Os | 2825 | 1798 | **1.57** |
| dot256 | -O2 | 2570 | 1798 | 1.42 |
| conv3x3 | -O0 | 16872 | 8052 | 2.09 |
| conv3x3 | -Os | 5311 | 2068 | **2.56** |
| conv3x3 | -O2 | 4944 | 2063 | 2.39 |

- **已得规律**（报告素材）：

1. dot256 的 1.57× 落在预测区间 1.3–1.6；逐拍归因 = 每迭代省约 4 拍（mul 多拍 FSM 停顿 2~3 拍 + 一条 add），lw×2 与循环控制两侧相同、省不掉。
2. conv3x3 的 2.56× **超出预测**——预加载+展开结构消除了内层循环控制开销，收益 = MAC 指令节省 + 循环展开节省。
3. 优化级别越低，加速比越趋近 1（绝对节省恒定，Amdahl 定律）；CFU 版 -Os/-O2 数字相同（`asm volatile` 固定指令序列），编译器优化只帮助软件版。

### 2.2 EXP-M：主实验（方案 A vs 方案 B）

- **变量**：CFU 微架构（单 MAC → 并行/打包 MAC）。
- **测量**：同 kernel、同优化级（-Os 为主）下的 cycle 与加速比；Vivado 资源与 Fmax。
- **步骤**：

1. 方案 B 设计定稿前，先写预测（相对方案 A 的提升幅度与依据）；
2. 功能对拍（扩充测试用例：负×正、大数单乘、INT8 溢出边界）；
3. kernel 级计时（dot256、conv3x3）；
4. 整网级：卷积算子完整接入 → LeNet 级小型 CNN 端到端推理，统计整网 cycle。

- **产出**：资源—性能权衡表 / 散点图（方案 A、方案 B 两个点：横轴资源，纵轴加速比）。

### 2.3 EXP-A：消融 / 参数实验

| 编号 | 变量 | 实验内容 | 预期回答的问题 |
| --- | --- | --- | --- |
| A1 | MAC 并行度 | 1 / 2 / 4 MAC 三档 | 收益是否随并行度线性？瓶颈何时从 MAC 转移到取指/load？ |
| A2 | 数据位宽 | INT32 vs INT8 packed（4 路/寄存器） | 位宽打包对 cycle 与资源的双重影响 |
| A3 | hazard 修复 | 前置 3 nop vs 修 `proc.v` 后去 nop | nop 税（每条 CFU +3 拍）占总耗时的比例；修复的真实收益 |
| A4 | 优化级别 | -O0 / -Os / -O2（Baseline 已有数据，复用） | Amdahl 效应验证 |
| A5 | kernel 规模 | dot 长度 256→更大；conv 输入 8×8→更大 | 加速比随规模的变化趋势（load 占比是否下降） |

A3 优先级最高：它是方案 B 的候选前置步骤，且直接对应已发现的上游框架缺陷。

### 2.4 EXP-F：异常与失败案例分析

已积累三个现成案例，论文"正确性验证与问题分析"章节素材：

| 编号 | 案例 | 状态 |
| --- | --- | --- |
| F1 | **上游框架 custom-0 load-use 冒险缺陷**：conv3x3 CFU 版对拍 5/36、"行冻结"；定位为 `proc.v` 的 `If_load_muldiv_use` 只把 CFU 列入生产者侧、作消费者紧跟 lw 时停顿不足；经 T1–T4 探针复现确认 | 已规避（预加载+展开 + 前置 nop），待根治（改 hazard 逻辑） |
| F2 | **-O0 编译失败** `impossible constraint in 'asm'`：funct3 的 "i" 约束依赖内联+常量传播，-O0 不内联；修复为宏字符串化（`#f3` 拼进指令文本） | 已修复 |
| F3 | **程序映像固化导致假数据**：`make run` 不重新编译，程序经 initf 烧入仿真器；改程序后必须 `make`（prog+build）再 `make run`；曾因此得到三组完全相同的假数据 | 已形成流程规范 |

F1 是答辩亮点：从现象 → 对照实验排除 → 探针定位 → 源码根因 → 规避与修复方案，是完整的调试方法论展示。

## 3. 测量方法学（已验证，冻结执行）

1. 计数：`pg_perf_reset → enable → 被测代码 → disable → cycle()`，夹 10 次取总，减去空夹（enable/disable 之间无代码）开销，除 10 得单次均值。
2. 初始化：确定性公式初始化输入数据，禁用 `rand`，保证可复现。
3. 顺序：CFU 与纯 C **先逐位对拍，通过后才计时**。
4. 构建：改程序后必须 `make OPT=<级别>`（prog+build，重新 Verilate 烧入程序）再 `make run`；只 `make run` 跑的是旧映像。
5. 记录：每组实验填实验记录卡（`experiments/expXX/`），数据进 `metrics.csv`，配置进 `config.yaml`，命令进 `command.txt`，分析进 `notes.md`。

## 4. 实验环境

- 处理器：CFU-Proving-Ground 自带 RVProc（RV32IM，5 级流水线 + 分支预测器）。
- 仿真：Verilator（CFU-PG 标准流程）。
- 综合：Vivado（版本与许可【待确认】）。
- 软件：RISC-V GCC 工具链，优化级 -O0/-Os/-O2。

## 5. 风险与降级

| 风险 | 影响 | 降级方案 |
| --- | --- | --- |
| 方案 B 并行化后时序不收敛 | C4 不满足 | 降并行度档位（4→2 MAC），或在论文中归因分析 |
| 整网接入工作量超期 | C6 延期 | 整网降级为"多尺寸 conv kernel 组"，仍覆盖 kernel 级证据链 |
| Vivado 环境/许可问题 | 资源表缺失 | 用 Yosys/nextpnr 开源综合给出近似资源数据并说明口径差异 |
| FPGA 实板调试卡住 | 拖垮进度 | 实板本就属拓展，直接放弃，保住仿真+综合 |
